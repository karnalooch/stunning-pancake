# T75 — transport and backup confidentiality

Status: **repo-side implementation**. Runtime/owner evidence is still reported separately; this document does not claim a public certificate, provider-managed backup setting, or physical home-lab run that has not been observed.

## Transport contract

### Public / production Django path

When `DEBUG=0`, the backend already fails closed toward HTTPS:

- `SECURE_PROXY_SSL_HEADER = ("HTTP_X_FORWARDED_PROTO", "https")` trusts the deployment proxy's forwarded scheme;
- `SECURE_SSL_REDIRECT = not DEBUG` redirects non-HTTPS requests;
- HSTS is enabled with subdomains outside debug mode;
- session and CSRF cookies are `Secure` outside debug mode;
- content-type sniffing, referrer policy and frame denial remain enabled.

The repository therefore proves the application-side HTTPS contract. It does **not** by itself prove the externally served certificate, load-balancer TLS policy, DNS, or provider configuration. Those remain runtime evidence when a release environment is selected.

### Pilot home lab

The pilot-local exception is deliberately narrower than a LAN HTTP deployment. `docker-compose.home.yml` binds the core pilot services only to `127.0.0.1` (PostgreSQL, Redis, backend, telemetry and GLOBAL_OWNER admin). The Android pilot reaches the host backend through `adb reverse`; cleartext HTTP is therefore confined to the host loopback path instead of being exposed on the LAN.

Optional routing/simulation/tracking/all-admin profiles are not part of this phone transport exception and must not be used as evidence that arbitrary LAN cleartext is approved.

## Backup confidentiality contract

`python scripts/home_lab.py backup` now streams `pg_dump` directly into an authenticated **AES-256-GCM** artifact:

- a dedicated 256-bit `BACKUP_ENCRYPTION_KEY` is generated by `python scripts/home_lab.py init` and stored only in ignored `.env.home`; the generated secret file is created with mode `0600` on POSIX (Windows relies on the user's filesystem ACL);
- the backup key is independent of Django `SECRET_KEY` and the telemetry JWT signing secret;
- backup artifacts use the suffix `.dump.enc`;
- no plaintext `.dump` is staged on the host or in the database container;
- restore first copies the encrypted input into a private ciphertext-only snapshot, then authenticates that snapshot completely before decrypted bytes from the same snapshot are released to `pg_restore`; this closes the verify/decrypt source-replacement window without plaintext staging;
- tampered, truncated or wrong-key artifacts fail closed;
- the encrypted artifact is best-effort `0600` on POSIX; Windows remains protected by the user's filesystem ACL plus content encryption;
- recovery evidence records the encryption algorithm and retention policy but never the encryption key.

## Retention and disposal

Canonical home-lab backup artifacts (`4velo-home-*.dump.enc`) have a maximum local retention of **30 days**. Every successful backup prunes older canonical encrypted artifacts. Unrelated files are never deleted by this cleanup.

This aligns with the T72 lifecycle boundary: active deletion/retention does not retroactively rewrite historical backups. A restored backup is first restored into the isolated verification database. Before any future procedure promotes restored data into a live service, the active T72 deletion and retention policy must be re-applied.

Provider-managed production backups are outside the home-lab implementation. Their encryption-at-rest, access control, retention and disposal must be verified against the chosen provider before a production release can claim that evidence.

## Verification

Repository gates cover:

- AES-GCM round trip;
- tamper and wrong-key rejection without releasing plaintext;
- source replacement between authentication and release cannot change the bytes being decrypted;
- private creation of the generated `.env.home` secret file on POSIX;
- generation of an independent backup key;
- rejection of plaintext `.dump` files by the restore path;
- 30-day canonical backup pruning;
- loopback-only pilot core port bindings;
- Django application-side HTTPS/HSTS/secure-cookie settings;
- Compose validation for base and optional home-lab profiles.

The physical T57 recovery drill and T76 Android/home-lab restart matrix remain environment evidence. T75 must not be used to mark those tranches complete.
