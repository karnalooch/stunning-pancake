# T91 — Final exact-RC mobile validation

**Status:** BLOCKED until real-device execution  
**Issue:** #323  
**Prerequisite:** T90 is DONE and the canonical Home Lab reaches `DEV ENV READY`  
**Applies to:** one exact pilot release-candidate SHA and its exact Android artifact

## Purpose

T91 is the final human mobile UI/runtime sign-off before T92 full pre-pilot regression. It validates the actual release candidate on a real Android device, including the critical ride flow and truthful failure/degraded states.

CI, emulator screenshots and `AUTOMATION_PASS` are required technical evidence, but they are not a substitute for the physical verdict.

## Candidate identity

Before starting, record one immutable candidate:

- clean Git SHA;
- APK SHA-256;
- package/version identity;
- CI workflow run id when using a published artifact;
- hashed device serial plus manufacturer/model/API/ABI.

Do not mix evidence from different SHAs or old installed builds.

## Canonical preparation

From a clean checkout at the exact candidate SHA, start the canonical Home Lab and prove runtime readiness:

```powershell
python scripts/dev_doctor.py
python scripts/home_lab.py config
python scripts/home_lab.py cold-start-smoke
```

The runtime proof must reach `DEV ENV READY`.

Then install and exercise the exact Android artifact with the existing harness:

```powershell
pwsh -NoProfile -File scripts/mobile-runtime-acceptance.ps1 -UseCiArtifact
```

With more than one connected Android device:

```powershell
pwsh -NoProfile -File scripts/mobile-runtime-acceptance.ps1 -UseCiArtifact -DeviceId <adb-serial>
```

If no successful exact-SHA CI artifact exists, use the documented local-build fallback in `MOBILE_RUNTIME_ACCEPTANCE_V1.md`.

## Reuse of T84 evidence

T84 and T91 are separate gates.

A T84 physical PASS may satisfy overlapping T91 observations only when all of the following are identical:

- Git SHA;
- APK SHA-256;
- package/version;
- physical Android device identity;
- tested scenario and state.

If any identity differs, or T84 did not cover a required T91 scenario, repeat that check on the exact release candidate.

## Required T91 physical sequence

1. Fresh first-use → Home without reviewer coaching.
2. Home → Start Ride → Active Ride.
3. Pause → Resume and verify stop protection.
4. Exercise a degraded GPS and/or offline state and confirm the UI tells the truth.
5. Exercise a pending/failure finalization or synchronization state and confirm it never impersonates durable success.
6. Complete a durable-success ride → Summary → Home.
7. Recheck the critical screens for Frozen UI hierarchy, readability, touch-target clarity and absence of legacy arcade/RPG chrome.
8. Record any defect with the exact SHA/APK/device identity and reproduction path.

Do not operate ride controls while riding or driving. Static/walking physical checks are sufficient where motion would be unsafe.

For T91, add the reviewer verdict and T91-specific observations to the issue or an attached evidence note while preserving the exact bundle identity.

## PASS criteria

T91 is PASS only when:

- T90 runtime readiness is proven for the candidate environment;
- the exact candidate has `AUTOMATION_PASS`;
- a real Android device executes the critical journey;
- required degraded/failure states are truthful;
- pending/failure Summary never presents durable success;
- no critical visual or interaction regression is observed;
- the reviewer records **PASS** against the exact candidate identity.

## FAIL

If a product/runtime defect is observed, open the smallest focused follow-up issue containing:

- exact Git SHA and APK hash;
- device context;
- reproduction path;
- expected vs actual behavior;
- screenshot/photo/log when useful.

T91 remains open until the fix is merged and the affected exact-RC check is repeated.

## BLOCKED

Use BLOCKED when the gate cannot be executed because of an external/environment limitation, for example:

- no authorized real Android device;
- no usable exact candidate artifact;
- ADB unavailable;
- required failure/degraded state cannot be reproduced safely.

Record the smallest next action. Missing physical evidence is never PASS.

## Completion boundary

T91 closes only after one exact candidate has both:

1. technical exact-artifact acceptance (`AUTOMATION_PASS`); and
2. explicit real-device reviewer **PASS** for the T91 sequence.

T91 does not replace T92. T92 remains the broader exact-SHA pre-pilot regression across mobile, backend, admin, recovery, security and required release gates.
